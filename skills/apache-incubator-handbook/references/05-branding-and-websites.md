# Branding, names, websites, downloads, and publicity

Last verified: 2026-08-02.

## Podling identity

- After acceptance and initial setup, use `Apache ProjectName` together with a
  clear statement that the project is incubating. `Apache ProjectName
  (Incubating)` is a common compact form.
- Repository README files should identify the podling as incubating and link to
  the disclaimer.
- Podling websites and documentation include a clear incubation disclaimer.
  Releases normally carry it in `DISCLAIMER` or `DISCLAIMER-WIP` beside
  `LICENSE` and `NOTICE`.
- A materially different disclaimer requires IPMC approval.

## Name and trademarks

- Perform the required name search and obtain the applicable Apache Brand
  approval before treating a name as cleared.
- Apache names, the feather, Incubator marks, and project logos are trademarks.
  Follow ASF attribution rules and do not combine ASF marks into a project logo
  without permission.
- A logo or old project mark contributed to a podling needs documented rights.
  Trademarks needed by the future TLP must be transferred to the ASF before
  graduation.

## Website checklist

- Serve the official project home from the project's `apache.org` domain.
- Keep website source in an ASF-controlled repository.
- Display the incubation disclaimer and appropriate Incubator identity.
- Provide clear project description, source repository, issue tracker,
  mailing-list/community links, license, security contact/process, and download
  path where applicable.
- Maintain required Apache/Incubator/trademark attribution and current project
  metadata such as DOAP where applicable.
- Keep the Incubator status page current; it is separate from the project site.

## Download page

- Link only approved official releases as releases.
- Provide the source distribution prominently; convenience binaries are
  secondary.
- Use the standard Apache download mechanism for artifacts.
- Link checksums, detached signatures, and `KEYS` through
  `https://downloads.apache.org/...`, and include verification guidance.
- Remove public recommendations and current-download links for obsolete
  releases; the archive retains historical copies.

## Publicity

- A project cannot present itself as an Apache podling before IPMC acceptance.
- During incubation, coordinate formal publicity and press activity through the
  applicable ASF publicity process. Do not issue independent press releases or
  imply full ASF endorsement.
- Release candidates are development-community material, not public releases.
- Announcements of approved releases point to the project download page, not a
  staging URL. Allow distribution synchronization before announcing.
