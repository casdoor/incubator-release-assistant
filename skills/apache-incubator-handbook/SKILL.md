# Apache Incubator Handbook

Use the bundled references as the first source of truth. They summarize official
ASF and Incubator material verified on 2026-08-02 and are organized so an Agent
does not need to search the web for ordinary incubation questions.

## Route the question

- Read `references/01-lifecycle-and-roles.md` for Champion, Sponsor, Mentor,
  IPMC, PPMC, committer, and podling lifecycle questions.
- Read `references/02-governance-and-reporting.md` for mailing lists,
  consensus, personnel decisions, reports, status pages, rosters, and records.
- Read `references/03-releases-voting-and-distribution.md` for ASF release
  policy, two-phase podling votes, signatures, KEYS, distribution, and downloads.
- Read `references/04-ip-and-licensing.md` for CLA/CCLA/SGA, provenance,
  headers, LICENSE/NOTICE, third-party works, and RAT interpretation.
- Read `references/05-branding-and-websites.md` for naming, disclaimers,
  logos, publicity, trademarks, website, and download-page presentation.
- Read `references/06-community-graduation-and-retirement.md` for community
  health, diversity, graduation readiness/process, or retirement.
- Read `references/07-infrastructure-accounts-and-security.md` for ASF accounts,
  mailing lists, repositories, infrastructure, durable records, secrets, or
  vulnerability handling.
- Read `references/official-sources.md` when the user needs authoritative links
  or when distinguishing policy from guidance.

Read only the relevant files. Do not load this handbook while executing the
separate `incubator-release-assistant` RC workflow unless the user asks an
incubation-policy question.

## Answering rules

1. Explain unfamiliar ASF terms in plain language.
2. Separate Foundation policy, Incubator policy, guidance, and project-local
   convention.
3. State the immediate next action, responsible role, public/private channel,
   and required evidence when the question is operational.
4. Do not invent current podling rosters, vote status, report deadlines, URLs,
   or templates. Those are live state and may require verification.
5. Do not treat this handbook as legal advice. For an unresolved fact-specific
   licensing question, direct the project through its Mentors to the official
   ASF legal or Incubator channel.

The mechanical commit-to-RC/sign/upload/public-verify workflow belongs to the
separate release Skill. Do not add handbook topics as executable release gates.
